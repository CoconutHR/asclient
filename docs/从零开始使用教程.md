# ASClient 从零开始使用教程

本文适合第一次接触 ASClient 的用户。按顺序读完并跟着操作，你将能够：

- 安装客户端并创建配置文件；
- 通过 Wi-Fi 或 USB 连上一台已开启 AScript 服务的 iPhone，并用 `doctor`/`status` 确认连接成功；
- 打开 Inspector，为目标 App 找到稳定的选择器；
- 运行第一个只读 Python 程序，再逐步使用点击、等待、输入等自动化能力；
- 按第 10 节的完整示例，组装一个可留证、可排查的自动化流程。

连接方式二选一即可：Wi-Fi 用户阅读第 4 节并跳过第 5 节；USB 用户重点阅读第 5 节。

完整参数、返回值和全部类成员请查阅 [API 使用参考](API使用参考.md)；生产环境规范请查阅[生产使用指南](生产使用指南.md)。

## 1. 开始前要知道的事

ASClient 是已运行 AScript 本地服务的 iPhone 的客户端，不会修改 IPA，也不会向手机安装组件。它连接两个设备端口：

| 端口 | 用途 | 默认值 |
| --- | --- | --- |
| HTTP 控制服务 | 截图、控件树、点击、文件和项目管理 | `9096` |
| 日志回显服务 | `log`、`deploy --logs` 与 Python 日志读取 | `10102` |

本文假设手机中已经开启 AScript 服务。请先确定采用其中一种连接方式：

1. Wi-Fi 局域网：电脑能直接访问手机的 `IP:9096`。
2. USB 隧道：电脑运行 `iproxy`，ASClient 通过本机 `127.0.0.1:9096` 访问手机。

不要在配置、代码、截图或日志中提交设备密码、UDID 和内网地址。

## 2. 安装 Python 与客户端

### 2.1 安装 Python

Windows 安装 Python 3.10 或更高版本后，重新打开命令提示符，检查：

```bat
py --version
py -m pip --version
```

如果 `py` 不存在，可使用已安装 Python 对应的 `python` 命令；下文以 Windows 推荐的 `py` 为例，macOS/Linux 将命令中的 `py` 替换为 `python3` 即可（例如 `py -m asclient status` 等价于 `python3 -m asclient status`）。macOS/Linux 通常使用：

```sh
python3 --version
python3 -m pip --version
```

### 2.2 取得并安装仓库

先取得私有仓库访问权限，然后克隆仓库或进入已有工作目录：

```bat
git clone https://github.com/CoconutHR/asclient.git
cd asclient
py -m pip install --user --upgrade .
```

`--user` 会安装到当前 Windows 用户目录，不需要管理员权限。验证安装：

```bat
py -m asclient help
```

### 2.3 直接使用 `asc` 命令

安装包提供 `asc` 命令。Windows 必须把 Python 用户 Scripts 目录加入 `PATH` 后才能直接调用它。先显示该目录：

```bat
py -m site --user-base
```

将输出路径后加上 `\Scripts`，例如 `C:\Users\你的用户名\AppData\Roaming\Python\Python312\Scripts`，加入用户 `PATH`。关闭并重新打开终端后验证：

```bat
asc help
```

在 Scripts 未配置、公司电脑限制修改 `PATH`，或希望最稳定兼容时，始终使用：

```bat
py -m asclient help
```

本文的 `py -m asclient` 可等价替换为已可用的 `asc`。例如 `py -m asclient status` 等价于 `asc status`。

### 2.4 更新客户端

在仓库根目录执行：

```bat
git pull --ff-only
py -m pip install --user --upgrade .
py -m asclient help
```

升级后，PyCharm 或 VS Code 如未刷新类型提示，请重启 IDE 的 Python 语言服务。生产设备应固定到已验收的提交或标签，而非无审查地更新 `main`。

**`asc` 命令用的是已安装的副本，不是仓库源码。** 这是一个容易困惑的地方：`git pull` 只更新仓库文件，`asc` 仍然运行上一次 `pip install` 装进 site-packages 的那份拷贝。因此拉取新版后若不重新安装，`asc` 会提示 `Unknown command`（新命令还不存在于旧副本中）。判断方法：

```bat
py -m asclient help <新命令>
asc help <新命令>
```

在仓库目录里，前者读仓库源码、后者读已安装副本。若前者正常而后者报未知命令，说明只是没重装。重新执行上面的 `pip install --user --upgrade .` 即可。

需要验证当前安装的版本时：

```bat
py -c "import asclient; print(asclient.__version__)"
```

## 3. 创建配置文件

ASClient 默认读取当前目录的 `asclient.json`，不依赖环境变量。推荐用 `init` 生成：

```bat
py -m asclient init
```

它会在当前目录写出一份包含全部配置键的文件，自动填入已安装的 `iproxy` 路径，并打印下一步提示。该命令不连接设备，手机还没准备好时也能先执行。已存在同名文件时它会拒绝覆盖（避免弄丢密码和 UDID），确需重建时加 `--force`；只想先看看内容用 `--print`。

也可以照旧从模板复制：

```bat
copy asclient.example.json asclient.json
edit asclient.json
```

`copy` 与 `edit` 是 Windows 写法：macOS/Linux 分别使用 `cp asclient.example.json asclient.json` 并用任意文本编辑器打开该文件。

生成的文件内容如下：

```json
{
  "language": "auto",
  "device": {
    "address": "127.0.0.1:9096",
    "password": "",
    "timeout": 15.0,
    "retries": 1
  },
  "tunnel": {
    "iproxy": "iproxy",
    "local_host": "127.0.0.1",
    "local_port": 9096,
    "remote_port": 9096,
    "local_log_port": 10102,
    "remote_log_port": 10102,
    "forward_logs": true,
    "udid": "",
    "startup_timeout": 8
  }
}
```

`device.address` 默认是 USB 隧道用的回环地址 `127.0.0.1:9096`。**如果你走 Wi-Fi 直连，必须把它改成手机 AScript 页面显示的地址**（也可以在生成时就指定：`py -m asclient init --device 192.168.3.17:9096`）。不改的话，第 4 节的 `doctor` 会因为找不到 `iproxy` 报一个红色错误——而 Wi-Fi 场景其实根本不需要 `iproxy`。

`language` 设为 `auto` 时，中文系统显示中文提示，其他系统显示英文；也可固定为 `zh-CN` 或 `en`。`timeout` 的单位是秒。`asclient.json` 已被 Git 忽略，不能提交到仓库。

逐项含义如下（`tunnel` 段仅 USB 场景需要，纯 Wi-Fi 使用时可忽略）：

| 配置键 | 默认值 | 含义 |
| --- | --- | --- |
| `language` | `auto` | 输出语言；`auto` 跟随操作系统 |
| `device.address` | `127.0.0.1:9096` | 手机 AScript 服务地址；Wi-Fi 场景须改为手机显示的地址 |
| `device.password` | `""` | 服务密码；留空表示不发送密码 Cookie |
| `device.timeout` | `15` | 单次请求超时秒数 |
| `device.retries` | `1` | 仅连接失败时的重试次数；HTTP 与业务错误不重试 |
| `tunnel.iproxy` | `iproxy` | `iproxy` 可执行文件名或绝对路径 |
| `tunnel.local_host` | `127.0.0.1` | 本机监听地址；只接受 `127.0.0.1` 或 `localhost` |
| `tunnel.local_port` / `remote_port` | `9096` / `9096` | 本机与手机端的控制端口 |
| `tunnel.local_log_port` / `remote_log_port` | `10102` / `10102` | 本机与手机端的日志端口 |
| `tunnel.forward_logs` | `true` | 是否同时转发日志端口 |
| `tunnel.udid` | `""` | 目标设备 UDID；多设备时必填 |
| `tunnel.startup_timeout` | `8` | 等待 `iproxy` 就绪的秒数 |

上表的默认值是 `init` 生成的内容。配置文件不是必需的：文件不存在时客户端使用内置默认值（`device.address` 为 `192.168.3.17:9096`，其余与上表相同），也可以每次都用命令行参数指定。注意内置默认地址与 `init` 生成的地址不同，这是首次使用时容易困惑的地方——用 `init` 建立配置后就以文件内容为准。

## 4. 方式一：Wi-Fi 局域网连接

### 4.1 配置设备地址

确认电脑和 iPhone 位于可互访的网络，且手机 AScript 页面显示的开发者地址类似 `192.168.3.17:9096`。编辑配置：

```json
{
  "device": {
    "address": "192.168.3.17:9096",
    "password": ""
  }
}
```

如服务设置了密码，填入 `password`；没有密码则保留空字符串。

### 4.2 验证连接并打开 Inspector

以下命令均为只读操作：

```bat
py -m asclient doctor
py -m asclient status
py -m asclient shot evidence\wifi-screen.png
py -m asclient inspect
```

`doctor` 输出类似下面这样（纯 Wi-Fi 使用时未安装 `iproxy` 只显示警告，可以忽略；只有第 5 节的 USB 隧道需要 `iproxy`，届时缺失才会显示为 `error`）：

```text
ASClient 环境诊断
[警告] 未找到 iproxy。仅 USB 隧道需要它，而当前 device.address 不是本机回环地址，可忽略本项。如需使用 USB，请安装受信任的 libimobiledevice，或用 doctor --fix-iproxy <路径> 写入已有 iproxy 的绝对路径。
[正常] 设备服务可访问，平台：iOS
[警告] 设备的 /api/status 存在已知兼容性问题，客户端已使用屏幕与前台应用信息降级；设备仍可用。原始错误：ObjCStrInstance ...
[正常] 本机端口 127.0.0.1:9096 可用于建立隧道
[正常] 日志端口可连接：192.168.3.17:10102
```

判断连接是否成功，看“设备服务可访问”与“日志端口可连接”两行；存在 `error` 检查项时命令退出码为 `1`。

`status` 的输出是 JSON，`"available": true` 说明控制服务可访问：

```json
{
  "available": true,
  "health": "degraded",
  "status_api_error": "ObjCStrInstance ...",
  "compatibility": {
    "status_api": { "state": "degraded", "issue": "ios_objc_property_callable" },
    "capabilities": { "screen": "available", "current_app": "available" }
  },
  "platform": "iOS",
  "logical_screen": { "width": 393.0, "height": 852.0 },
  "screen": { "width": 1179.0, "height": 2556.0 },
  "current_app": { "name": "设置", "bundle_id": "com.apple.Preferences", "pid": 123 }
}
```

某些 iOS 服务版本可能显示 `status_api_error`，但只要仍返回 `screen` 与 `current_app`，即为已知的兼容降级，不代表连接失败；字段可能随设备与版本变化，判断连接是否成功以 `available` 为准。

`inspect` 会打开仅监听本机的中文控件检查器。确认顶部的应用名称、Bundle ID、PID 与手机前台应用一致；点击截图可读取物理像素“动作坐标”。

不想修改配置文件、只想临时连另一台手机时，用全局 `--device` 覆盖（注意它必须写在子命令之前）：

```bat
py -m asclient --device 192.168.3.25:9096 status
py -m asclient --device 192.168.3.25:9096 inspect
```

`--password`、`--timeout`、`--lang` 同理，都是只影响本次命令的全局参数。

## 5. 方式二：USB 隧道连接

USB 适用于电脑和手机不在同一网段、不希望使用手机热点或 Wi-Fi 受隔离的情况。隧道会同时映射控制端口和日志端口：

```text
127.0.0.1:9096  -> USB -> iPhone:9096
127.0.0.1:10102 -> USB -> iPhone:10102
```

隧道有两种用法，按场景选择：交互式排错、配合 CLI 命令时用 5.2 的前台 `tunnel` 命令；自动化逻辑写在 Python 脚本或 CI 里时，推荐 5.3 的 `AScriptTunnel`，由 `with` 语句管理启动和清理，不需要保持额外的终端。

### 5.1 准备 `iproxy`

先用 USB 连接 iPhone，并在手机上完成“信任此电脑”。ASClient 不会自动下载 `iproxy`，请通过受信任渠道安装 libimobiledevice。

Windows 安装后检查：

```bat
where iproxy
iproxy --help
```

macOS 可使用：

```sh
brew install libimobiledevice
which iproxy
iproxy --help
```

如果 Windows 找不到 `iproxy.exe`，将其绝对路径写入 `asclient.json`。JSON 的反斜杠必须转义：

```json
{
  "tunnel": {
    "iproxy": "C:\\tools\\libimobiledevice\\iproxy.exe"
  }
}
```

也可让诊断命令经确认后写入该路径：

```bat
py -m asclient doctor --fix-iproxy "C:\tools\libimobiledevice\iproxy.exe"
```

### 5.2 改为本机地址并启动隧道

将配置中的地址改为本机回环地址：

```json
{
  "device": {
    "address": "127.0.0.1:9096"
  }
}
```

多台 iPhone 同时连接时，在 `tunnel.udid` 中填入目标设备 UDID。接着打开两个终端。

终端 A 保持隧道运行：

```bat
py -m asclient tunnel
```

终端 B 验证和使用：

```bat
py -m asclient doctor
py -m asclient status
py -m asclient log 10
py -m asclient inspect
```

不要关闭终端 A；按 `Ctrl+C` 会同时停止两条转发。默认转发 `10102` 日志端口，因此不要随意使用 `--no-logs`，否则 `log` 和 `deploy --logs` 无法通过 USB 工作。

本机 `9096` 或 `10102` 已被其他程序占用时，改用其他本地端口，但要记住 `tunnel` 只建立映射、不会自动改配置，业务命令必须同步指向新端口：

```bat
py -m asclient tunnel --local-port 19096 --local-log-port 11002
py -m asclient --device 127.0.0.1:19096 status
```

需要注意的是，USB 隧道的本机监听地址只能是回环地址（`127.0.0.1` 或 `localhost`），没有把它绑定到局域网网卡的参数——`tunnel` 只提供端口和 UDID 层面的覆盖。可覆盖参数的完整列表、多设备并行的端口分配方案和运维要求见 [USB 隧道运维指南](USB隧道运维指南.md)。

### 5.3 在 Python 中管理隧道（脚本推荐）

自动化本身写在 Python 里时，不需要终端 A 和终端 B：脚本自己启动隧道、完成操作、退出时自动清理。

```python
from asclient import AScriptTunnel, connect

with AScriptTunnel.from_config() as tunnel:   # 读取 asclient.json 的 tunnel 段
    device = connect(tunnel.address)          # tunnel.address 即 127.0.0.1:9096
    print(device.client.status())
    print("日志地址：", tunnel.log_address)    # 127.0.0.1:10102
    device.client.save_screenshot("evidence/usb-screen.png")
# with 结束（包括中途抛异常）时自动停止两条映射
```

要点：

- `from_config()` 与 CLI `tunnel` 命令读取同一份 `asclient.json`，优先级为“显式参数 > 配置文件 > 内置默认值”。多台 iPhone 时用 `from_config(udid="设备UDID")` 临时覆盖配置，其余（`iproxy` 路径、端口等）继续沿用配置；配置文件不存在时退回内置默认值，不确定配置是否被读取时可用 `py -m asclient doctor` 检查。
- `AScriptTunnel` 默认同时映射日志端口 `10102`，脚本内 `client.logs()`、`wait_for_log()` 可直接使用；不需要日志时传 `forward_logs=False`。
- 脚本直接使用 `tunnel.address` 连接，`asclient.json` 的 `device.address` 不必改成 `127.0.0.1`，可保持 Wi-Fi 地址供 CLI 日常使用。想沿用配置中的密码和超时，复制设备配置后覆盖地址即可：

```python
from asclient import AScriptTunnel, connect
from asclient.config import device_options, load_config

options = device_options(load_config())   # 沿用配置中的密码、超时等
with AScriptTunnel.from_config() as tunnel:
    options["address"] = tunnel.address   # 地址改用本机隧道
    device = connect(**options)
    print(device.client.status())
```

- 不想读配置、需要完全显式控制时，也可以直接构造 `AScriptTunnel(executable="iproxy路径", udid=...)`。注意直接构造不读取 `asclient.json`，且字段名与配置键不同（`executable` 对应配置的 `iproxy`）；无特殊需求时优先使用 `from_config()`。

两种用法的常见组合：调试阶段在终端跑 `tunnel` 命令，配合 CLI 和 Inspector 观察设备；脚本定型后改为 `AScriptTunnel.from_config()` 单进程运行，便于在 CI 中执行。

## 6. 第一个程序：Hello World

先运行一个不会点击、输入、上传或删除任何内容的脚本。新建 `hello_asclient.py`：

```python
from pathlib import Path

from asclient import AScriptClient


def main() -> None:
    # 地址从 asclient.json 读取时可自行填入，也可在此处直接指定。
    client = AScriptClient("192.168.3.17:9096", timeout=15)
    status = client.status()
    print("已连接：", status["available"])
    print("当前应用：", status.get("current_app"))
    print("物理分辨率：", client.screen_size())

    output = Path("evidence") / "hello-screen.png"
    output.parent.mkdir(exist_ok=True)
    print("截图已保存：", client.save_screenshot(output))


if __name__ == "__main__":
    main()
```

将脚本里的地址改为自己的 Wi-Fi 地址；USB 模式则填 `127.0.0.1:9096`，并确保隧道仍在运行。执行：

```bat
py hello_asclient.py
```

成功后会输出类似：

```text
已连接： True
当前应用： {'name': '设置', 'bundle_id': 'com.apple.Preferences', 'pid': 123}
物理分辨率： {'width': 1179.0, 'height': 2556.0}
截图已保存： D:\work\asclient\evidence\hello-screen.png
```

并生成 `evidence\hello-screen.png`。如果这一步成功，截图、控件树、OCR、图像匹配和自动化对象 API 的基础连接都已具备。

希望让脚本和 CLI 共用配置时，可在 Python 中读取同一配置：

```python
from asclient import AScriptClient
from asclient.config import device_options, load_config

options = device_options(load_config())
client = AScriptClient(**options)
print(client.status())
```

## 7. 第一次定位控件：使用 Inspector

1. 先在手机上打开要分析的页面。
2. 运行 `py -m asclient inspect`，终端显示实际访问地址并自动打开浏览器：

```text
Inspector 已启动：http://127.0.0.1:53217/。按 Ctrl+C 停止。
```

3. 顶部确认当前 App 信息；选择“智能”模式并点击“刷新”。
4. 点击截图或控件树节点，查看原始属性、矩形和候选 Python 选择器。
5. 点击“验证选择器”。仅当结果为“唯一匹配”时，才将其作为稳定选择器候选。
6. 需要图片模板时点击“裁剪保存”，在截图上拖拽矩形；PNG 会保存到启动 Inspector 的当前目录。

页面布局如下，两条分隔线可拖动，中间截图始终等比缩放：

```text
┌───────────────────────────────────────────────────────────────────────┐
│ ASClient 控件检查器  设置 | com.apple.Preferences | PID 123  动作坐标：-- │
│ [智能▾] [刷新] [裁剪保存] [□ 实时刷新]                    42 个节点      │
├───────────────┬─────────────────────────────┬──────────────────────────┤
│ 搜索控件树     │                             │ 类型  XCUIElementType…  │
│ ┌───────────┐ │                             │ name  login_button      │
│ │ ▸ 应用    │ │        当前截图              │ label 登录              │
│ │  ▸ 窗口   │ │   （点击可读取“动作坐标”，    │ rect  …                 │
│ │   ▸ 按钮  │ │     并选中对应控件）          │ ──────────────          │
│ │   ▸ 输入  │ │                             │ Python 选择器           │
│ └───────────┘ │                             │ device.selector()…      │
│               │                             │ [复制选择器] [验证选择器] │
└───────────────┴─────────────────────────────┴──────────────────────────┘
```

控件树为空并不表示 ASClient 不可用，只表示当前 App 页面没有暴露可用于语义定位的树。此时应使用截图、OCR、图色或比例坐标。

### 7.1 Inspector 的地址与端口

初学者最容易混淆的是这里有两个“地址”：

- **设备地址**：Inspector 去连哪台手机。它不属于 `inspect` 的参数，而是沿用全局配置——配置文件的 `device.address`，或临时用全局 `--device` 覆盖。
- **Inspector 地址**：浏览器访问 Inspector 网页的地址，由 `inspect --host` 和 `--port` 控制，默认 `127.0.0.1` 加随机端口。

```bat
py -m asclient --device 192.168.3.25:9096 inspect --port 8765 --no-browser
```

上面这条命令的含义是：连接 `192.168.3.25` 这台手机，Inspector 固定监听 `http://127.0.0.1:8765/`，且不自动打开浏览器（适合远程终端或需要手动选浏览器的场景）。`--port` 默认值 `0` 表示由系统分配随机空闲端口，因此每次启动的端口号都不同，必须从终端输出的那一行 URL 中读取。

`--host` 存在，但**默认值 `127.0.0.1` 就是正确答案**。Inspector 的接口没有鉴权，任何能访问到它的人都能读取你手机的截图和控件树，所以不要改成 `0.0.0.0` 或局域网 IP。同理，裁剪图固定保存到启动命令时的当前目录，CLI 不提供改目录的参数；确实需要指定时用 Python 的 `serve(client, output_dir="evidence")`。

## 8. 常见错误与排查顺序

遇到问题先运行：

```bat
py -m asclient doctor --report evidence\doctor.json
```

该命令默认只读，不会安装软件、关闭其他程序或修改手机。下面是常见情况：

| 表现 | 检查与处理 |
| --- | --- |
| `No module named asclient` | 回到仓库根目录运行 `py -m pip install --user --upgrade .`，确认 IDE 和终端使用同一个 Python。 |
| `'asc' 不是内部或外部命令` | 使用 `py -m asclient`，或按 2.3 将用户 `Scripts` 目录加入 `PATH`。 |
| 连接超时（`无法连接 AScript 设备` / `cannot reach AScript device`） | Wi-Fi 时核对手机开发者地址、网络互访、服务开关和密码；USB 时确认终端 A 的隧道还在运行。 |
| 找不到 `iproxy` | Wi-Fi 场景 `doctor` 只显示警告、可忽略；需要 USB 时先手工安装受信任的 libimobiledevice，再用 `doctor --fix-iproxy` 写入已确认的绝对路径。 |
| 本地端口被占用 | 确认是否已有 ASClient 隧道；否则关闭已知占用者，或更改 `tunnel.local_port` 与 `device.address`。不要盲目结束未知进程。 |
| `status_api_error` | 若同时有 `available: true`、`screen` 和 `current_app`，这是已知兼容降级；仍可继续截图、Inspector 和多数操作。 |
| Inspector 没有控件节点 | 切换到目标 App 的可访问页面，尝试“完整”模式；仍为空则使用 OCR、图片或坐标方案。 |
| 点击位置偏移 | 所有绝对坐标使用截图的物理像素。先用 Inspector 的“动作坐标”或 `screen_size()`，不要使用 `logical_screen`。 |
| 图像找不到 | 确保模板来自相同分辨率、缩放和页面状态；降低 `confidence` 前先检查裁剪区域和图片是否正确。 |

诊断报告不包含设备密码，可作为问题反馈的证据。反馈时还应附上客户端版本、Git 提交、iOS/AScript 版本、目标 App 版本和完整错误文本。

## 9. 功能示例

以下示例默认已建立 `client` 或 `device` 连接。`timeout`、`interval`、`duration` 的单位都是秒；只有带 `_ms` 后缀的参数才是毫秒。

### 9.1 状态、截图、控件树与 OCR（只读）

```python
from asclient import AScriptClient

client = AScriptClient("192.168.3.17:9096")
print(client.status())
client.save_screenshot("evidence/screen.png")
open("evidence/page.xml", "w", encoding="utf-8").write(client.ui_xml(mode="smart"))

# 结构化 OCR：每个条目含 text、物理像素 rect、confidence。
result = client.ocr()
for item in result.items:
    print(item.text, item.rect, item.confidence)
```

CLI 等价示例：

```bat
py -m asclient status
py -m asclient shot evidence\screen.png
py -m asclient dump evidence\page.xml --mode smart
py -m asclient ocr
```

### 9.2 语义控件定位与等待

```python
from asclient import connect

device = connect("192.168.3.17:9096")
login = device(text="登录", class_name="XCUIElementTypeButton")
element = login.get(timeout=10)  # 最多等待 10 秒，未找到返回 None
if element is None:
    raise RuntimeError("登录按钮未在 10 秒内出现")
print(element.info)

# 仅在已确认业务允许时执行：
element.click()
```

优先使用 Inspector 验证后的 `name`、`label` 或组合条件，避免仅按坐标或索引定位。

### 9.3 物理坐标与比例坐标

```python
from asclient import AScriptClient

client = AScriptClient("192.168.3.17:9096")
print(client.screen_size())  # 例如 {'width': 1179.0, 'height': 2556.0}，物理像素

# 以下会改变手机界面：先确认目标页面正确。
client.tap(590, 2300)
client.tap_relative(0.5, 0.92)
client.swipe_relative(0.5, 0.80, 0.5, 0.25, duration=0.45)
```

CLI 的改变状态命令必须显式确认：

```bat
py -m asclient --yes tap-rel 0.5 0.92
py -m asclient --yes swipe-rel 0.5 0.80 0.5 0.25 --duration-s 0.45
```

### 9.4 比例裁剪截图

```python
client.save_screenshot_crop_relative(
    "evidence/bottom.png", left=0, top=0.5, right=1, bottom=1
)
```

矩形顺序为 `left, top, right, bottom`，范围是 `0..1`；示例保存屏幕下半部分。

### 9.5 等待图片、消失后继续与自动滚动

```python
# 默认先等待一个 interval 再检查；initial_delay=False 表示立刻检查一次。
match = client.wait_image(
    "assets/login.png", confidence=0.92, timeout=15,
    interval=0.5, initial_delay=False, log=True,
)
print(match.center)

# loading 图标消失后再继续；region_relative 为比例区域 left, top, right, bottom。
client.wait_image_gone(
    "assets/loading.png", confidence=0.85, timeout=20,
    interval=0.5, region_relative=(0.75, 0.85, 1, 1), log=True,
)

# 手指向上滑动以翻到下一屏，直到找到目标图；总超时或最大滑动次数任一到达即停止。
target = client.scroll_until_image(
    "assets/target.png", direction="up", confidence=0.90,
    timeout=30, max_swipes=8, interval=0.5, duration=0.5, log=True,
)
```

模板必须在相同物理分辨率、缩放和界面状态下采集。`log=True` 用于输出每轮匹配情况，排查失败时再开启即可。

### 9.6 输入文本与返回主屏幕

```python
# 以下均会改变手机状态。
client.home()
client.input_text("你好", interval_ms=80)
```

输入前必须先通过点击或语义选择器取得正确焦点；`home()` 会返回系统主屏幕。在生产脚本中，执行动作前先使用选择器、当前 App 或截图验证页面状态，避免因页面跳转而误操作。

### 9.7 长按、双击与拖拽

```python
# 以下均会改变手机状态。duration 单位是秒；duration_ms 是毫秒兼容参数。
client.long_press(600, 1200, duration=0.8)                 # 绝对坐标长按
client.long_press_relative(0.5, 0.5, duration=0.8)          # 比例坐标长按
client.double_tap(600, 1200)                                # 双击
client.drag(200, 1000, 900, 1000, duration=0.5)             # 拖拽
client.drag_relative(0.2, 0.5, 0.8, 0.5, duration=0.5)      # 比例坐标拖拽
```

元素层等价入口：

```python
element.long_click(duration=0.8)
element.double_click()
element.drag_to(800, 1200, duration=0.5)
element.drag_to_relative(0.8, 0.5)
```

### 9.8 颜色断言与 OCR 文本查找

颜色输入统一支持 `(r, g, b)` 元组、`#RRGGBB` / `#RRGGBBAA` 字符串和 `PixelColor` 对象；返回值都是 `PixelColor`，用 `.rgb` / `.rgba` / `.hex` 取不同表达。

```python
# 断言某点颜色；tolerance 是每通道容差，默认 0 表示精确匹配。
client.assert_color(100, 200, "#FFFFFF", tolerance=3)
client.assert_color_relative(0.5, 0.92, (255, 255, 255))

# 区域内查找 / 统计颜色；同一帧内多次查询请先 capture_frame()。
frame = client.capture_frame()
point = frame.find_color("#FF0000", region=(0, 1800, 1179, 2556))
count = frame.count_color((255, 255, 255), region_relative=(0, 0.7, 1, 1))
```

OCR 文本查找与等待（无需控件树的语义降级方案）：

```python
# 返回所有包含"登录"的条目，每项含 .text / .rect（物理像素）/ .confidence。
matches = client.find_ocr_text("登录", region_relative=(0, 0.3, 1, 0.8))

# 等待屏幕出现指定文字；超时抛 LookupError。
client.wait_ocr_text("登录成功", timeout=10)
```

### 9.9 等待前台应用与原子点击

```python
# 等目标 App 成为前台；也可传谓词函数。超时抛 LookupError。
client.wait_current_app("com.example.app", timeout=10)

# 在同一设备锁内"查询唯一元素并立即点击"。
# 0 个或多个匹配都会抛 LookupError，不会误点；适合替代 exists + click 组合。
device.click_if_unique(
    device.selector().name("submit_button"),
    timeout=10,
    duration=0.02,
)
```

`click_if_unique` 与 `Run` 组合时可以直接作为步骤动作：

```python
run.step("点击提交", lambda: device.click_if_unique(device.selector().name("submit_button")))
```

### 9.10 项目上传、运行和日志

准备入口文件 `demo.py`：

```python
print("ASCLIENT_DEMO_OK")
```

然后执行：

```bat

```

该命令会上传入口文件、运行项目、收集一段日志并保存截图，因会写入手机项目目录而要求 `--yes`。USB 模式需保持日志端口 `10102` 映射。项目文件和目录管理另见 API 参考的“项目与远程文件 API”。

## 10. 完整流程示例

前面的示例都是单个能力。下面把它们组装成一个真实的自动化流程：登录 → 等待首页 → 断言成功，每一步都会留证。完整可直接运行的版本在仓库 [examples/完整流程示例.py](../examples/完整流程示例.py)，其中的选择器是占位值，需先用 Inspector 验证后替换。

```python
from asclient import Run, connect
from asclient.config import device_options, load_config

# ―― 占位选择器：用 Inspector 验证为“唯一匹配”后替换 ――
USERNAME_INPUT = "username_input"   # 用户名输入框：name
PASSWORD_INPUT = "password_input"   # 密码输入框：name
LOGIN_BUTTON = "登录"               # 登录按钮：label 文本
HOME_MARK = "home_screen"           # 登录成功后的首页标识：name

def main() -> None:
    options = device_options(load_config())   # 与 CLI 共用 asclient.json
    device = connect(**options)

    with Run(device, artifacts_root="artifacts") as run:
        # 断言两个关键控件都存在且唯一；失败会自动截图、保存控件树
        # 并写入 manifest.json，然后原样抛出异常。
        username = run.assert_unique(device.selector().name(USERNAME_INPUT))
        password = run.assert_unique(device.selector().name(PASSWORD_INPUT))

        # set_text 会先点击控件取得焦点再输入。
        run.step("填写用户名", lambda: username.set_text("demo@example.com"))
        run.step("填写密码", lambda: password.set_text("demo-password"))

        # click_if_unique 在同一设备锁内查询唯一元素并立即点击：
        # 0 个或多个匹配都会抛 LookupError，避免 exists + click 的竞态。
        run.step("点击登录", lambda: device.click_if_unique(device.selector().text(LOGIN_BUTTON)), capture_after=True)
        run.wait(device.selector().name(HOME_MARK), timeout=15, name="等待首页")

        print("登录流程通过，证据目录：", run.directory)

if __name__ == "__main__":
    main()
```

阅读这段示例的要点：

- 选择器集中放在文件顶部常量里，不要散落在流程代码中间；
- 每个动作前都先确认页面状态（`assert_unique`、`wait`），不要点击后直接 `sleep`；
- `Run` 的每个步骤都会记录到 `artifacts\<运行ID>\manifest.json`，失败时不需要额外代码就有截图、XML 和设备状态；
- 步骤名会直接生成证据文件名（如 `填写用户名_failure.png`），中文可用；`/`、`\`、`:` 等文件名非法字符会被替换为下划线；
- 页面跳转后 `UiObject` 是旧快照，不要复用上一页拿到的元素继续操作。

## 11. 等待与超时模型

所有轮询类 API 的 `timeout` 单位都是秒，但默认值和超时后的行为不同，写脚本前先过一遍这张表：

| 调用 | 默认超时 | 超时后行为 |
| --- | --- | --- |
| `device(...).get()` / `device.find(selector)` | `0`（立即查询一次） | 返回 `None` |
| `device(...).click_exists(timeout=...)` | `0` | 返回 `False`，不报错 |
| `device(...).wait_gone()` | `10` | 返回 `False` |
| `device.wait(selector)` | `10` | 抛出 `LookupError` |
| `device.wait_any(selectors)` | `10` | 抛出 `LookupError` |
| `device.click_if_unique(selector)` | `0` | 抛出 `LookupError`（0 个或多个匹配） |
| `device.scroll_until_element(selectors)` | `20`，且最多滑动 `10` 次 | 抛出 `LookupError` |
| `run.wait(selector)` | `10` | 采集证据后抛出 `LookupError` |
| `client.wait_image()` / `client.tap_image()` | `10` | 抛出 `TimeoutError` |
| `client.wait_any_image()` | `10` | 抛出 `TimeoutError` |
| `client.wait_image_gone()` | `10` | 返回 `False` |
| `client.scroll_until_image()` | `20`，且最多滑动 `10` 次 | 抛出 `TimeoutError` |
| `client.wait_ocr_text()` | `10` | 抛出 `LookupError` |
| `client.wait_current_app()` | `10` | 抛出 `LookupError` |
| `client.wait_for_log(pattern)` | `10` | 返回 `None` |

选择哪一类的原则：

- “没找到”是正常分支时（例如弹窗可能不出现），用返回 `None`/`False` 的接口：`get()`、`click_exists()`、`wait_gone()`，在代码里显式处理。
- 缺失即为失败时（关键按钮、成功页标识），用抛异常的接口：`device.wait()`、`run.wait()`、`wait_image()`，让失败尽早暴露，避免后续步骤在错误页面上继续操作。
- 图片等待默认先等一个 `interval`（默认 0.5 秒）再做第一次探测，适合页面正在加载的场景；需要立即探测时传 `initial_delay=False`。
- 控件等待的轮询间隔默认最多 0.3 秒，可通过 `interval` 参数调整；不要在等待 API 外再叠加 `time.sleep()`。
